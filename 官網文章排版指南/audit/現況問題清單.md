# 官網文章排版現況問題清單

> **一句話診斷**：規範 v1.0 寫了很多好原則（行高 1.8、字體 Microsoft JhengHei、字距規劃），但**實際上線 CSS 沒吃到規範**。真正跑在瀏覽器的 p 元素行高是 **1.20**，不是 1.8。讀起來擠、累、壓迫感，不是錯覺，是測出來的事實。

---

## 🔴 P0 — 致命問題（決定性影響可讀性）

### 1. 段落行高 line-height 只有 1.20（規範說 1.8）
- **實測**：`<p>` 的 `font-size: 20px` / `line-height: 24px` → **ratio 1.20**
- **規範寫的**：line-height 1.8
- **為什麼**：CSS 用了絕對值 `line-height: 24px` 繼承自 body，沒有被 article 內容區覆蓋
- **後果**：中文段落行與行之間完全擠在一起，是「文字牆」感最大元兇
- **修復**：把 `article p { line-height: 1.9; }`（用倍數）

### 2. h3 的左邊框沒吃到（規範說 4px 藍色邊框）
- **實測**：`h3 { border-left: 0px none rgb(73, 80, 87); }`
- **規範寫的**：`border-left: 4px solid #2c5aa0`
- **後果**：章節層級視覺消失，讀者看不到結構
- **修復**：CSS 具體性問題，需要用 `.blog-detail h3` 提升權重

### 3. 桌機沒有目錄（TOC）
- **實測**：`hasToc: false`
- **規範寫的**：有灰底目錄區塊
- **後果**：3500 字文章沒有導航，讀者無法跳讀，只能線性閱讀
- **修復**：
  - 文章轉 HTML 時強制產生目錄
  - 桌機 sticky 側欄、手機頂部收合

### 4. H3 字階與 body 幾乎一樣大
- **實測**：body 20px、h3 也是 20px（手機視口），字級完全無差異
- **後果**：章節標題讀不出是標題
- **修復**：h3 至少 24–26px、加粗、保留色差與邊框

## 🟠 P1 — 嚴重問題（顯著影響閱讀體驗）

### 5. 字體 stack 錯序（英文字體排在中文前面）
- **實測**：`"Open Sans", 微軟正黑體, Arial, Helvetica, sans-serif, "STHeiti Light"...`
- **問題**：Open Sans 不含中文 → fallback 規則下，Mac/iOS 會被拉到 STHeiti Light（不是最佳 PingFang）
- **修復**：改成 `"PingFang TC", "Noto Sans TC", "Microsoft JhengHei", "微軟正黑體", system-ui, sans-serif`

### 6. 主文色是棕色 rgb(88,54,40)，不是規範的 #333
- **實測**：`color: rgb(88, 54, 40)` → #583628
- **問題**：棕色 + 白底對比度 7.9:1（還 OK），但品牌調性不一致，規範寫 #333
- **修復**：統一為 `#2a2a2a` 或保留棕但集中管理

### 7. 沒有 letter-spacing 優化
- **實測**：`letter-spacing: normal`
- **規範提到但未實作**：中文建議 0.02–0.04em 呼吸感
- **修復**：`body { letter-spacing: 0.02em; }`

### 8. 紅色 strong 密度過高（23 個 strong / 64 段 ≈ 每段 0.36 個）
- **觀察（手機截圖明顯）**：幾乎每段都有紅字，讀者眼睛被拉扯
- **經驗法則**：強調色一章節 ≤ 3 處才有強調效果
- **修復**：
  - strong 預設**只加粗，不變色**
  - 紅色只保留「關鍵句」（每章最多 1–2 處）
  - 新增「重點卡」元件承接 TL;DR 內容

### 9. 沒有古籍引文框（宗教文章核心需求）
- **實測**：`blockquote: 0`
- **問題**：《陀羅尼經》《北斗經》這類原文引用只能塞進 p 裡，沒有視覺區分
- **修復**：新增 `.quote-ancient` 元件（米色底 + 左邊框 + serif 字體）

### 10. 沒有 h4（規範有定義但實際未使用）
- **實測**：`h4: 0`
- **問題**：章節內再分層時沒有合適元素，只能繼續用 p + strong 混亂堆疊
- **修復**：在 HTML skill 裡強制章節內分段用 h4（橘色 #e67e22）

## 🟡 P2 — 體驗層改善項

### 11. 內容寬度 770px（桌機）— 每行字數偏多
- 20px 字、770px 寬 → 約 38 字/行（中文舒適閱讀 25–35 字）
- **修復**：改為 680px 內文 + 側欄目錄 / 相關文章

### 12. 文末無明確 CTA
- 抓到 11 個 CTA 字樣，但多為選單連結，**沒有針對性「預約供養 / 加 LINE」按鈕**
- 讀者讀完 3500 字流量就散了
- **修復**：文末固定放「這篇讓你想為家人祈福嗎？→ 線上供養預約」紅色大按鈕

### 13. 手機 font-size 沒縮（桌機手機都 20px）
- 手機視口 360px 內容寬 × 20px → 約 18 字/行，偏短
- **修復**：手機降到 18px、行高維持 1.9

### 14. 圖片沒有圖說
- 6 張圖但沒有 `<figcaption>`
- **修復**：HTML skill 輸出時強制圖片下方帶圖說（灰字、比內文小）

### 15. Sticky 元素只有 social-float 和 scroll_top
- 目錄、進度條都沒有
- **修復**：加頂部 3px 閱讀進度條 + 桌機 sticky TOC

## 🎯 建議改進優先級

### 階段 2A — 立刻能做的 CSS 熱修（1–2 天）
不動規範、不動 skill，直接在網站 CSS 補丁：
1. **修 p line-height 1.20 → 1.9**（最高收益單點，一行 CSS 改完）
2. 修 h3 border-left 權重問題
3. 手機 p 降到 18px
4. body letter-spacing 0.02em
5. 頂部加 3px 閱讀進度條（15 行 JS）

> **預期效果**：這 5 項改完，「不好閱讀」感受會降 60%。成本極低。

### 階段 2B — 規範 v2.0 修訂（3–5 天）
1. 重寫 `HTML文章排版標準.md` → v2.0
2. 新增六個元件：古籍引文框 / 重點卡 / 小知識框 / 時間線 / 對照表 / 文末 CTA
3. 字體 stack 換 PingFang TC 優先
4. 強調色密度規則（每章 ≤ 2 處紅）
5. 同步更新 `writing-style` skill 的 HTML 輸出模板

### 階段 2C — 體驗層（可選，1 週）
1. 桌機 sticky TOC 側欄
2. 相關文章推薦
3. 文章頁骨架 + Schema.org Article
4. 深色模式友好
